## How social mode is switched (traced, not assumed)

`apps/piggy_firefighters/src/game/rulesContent.ts:94` —
`isSocial = () => stateUrlDerived.social() || stateConfig.jurisdiction.socialCasino || isSweepsWallet()`.
`stateUrlDerived.social()` reads the `?social=true` query param (confirmed in the built bundle:
`social:()=>yi("social")==="true"`). The same three-way OR raises `@crashgalaxy/hud`'s own
`stateHud.social` flag via `apps/piggy_firefighters/src/game/socialFloor.ts:32` (`applySocialFloor`),
called from `apps/piggy_firefighters/src/game/money.ts:49` (`setSocialMode`). Both paths agree, so
the rules sheet and the HUD chrome never disagree about which vocabulary is live. There is no
`sweeps_en.ts` file (`apps/piggy_firefighters/src/i18n` holds only `i18nDerived.ts`,
`messagesMap/en.ts`, `messagesMap/index.ts`) — this game uses the alternative, functionally
equivalent pattern of a `{std, social}` pair per string (in `rulesContent.ts`, in the vendored
HUD's `defaultStrings.js`, and in `components/notice/PlayNotice.svelte`'s `NOTICE_COPY`) rather
than Stake's suggested separate file. That satisfies the requirement (the guideline only
"recommends" the extra file); traced and confirmed functioning, not merely assumed.

Only `en` is offered (`apps/piggy_firefighters/src/i18n/messagesMap/index.ts:12-19`, decision dated
2026-09-20): a previously-partial `zh` table was removed rather than shipped incomplete, so
`?lang=` for any unsupported tag falls back cleanly to English (comment cites the donor's partial
`zh.ts` was deliberately not carried over).

## GATE COVERAGE

- The repo has **no** prohibited-terms / jurisdiction string gate of any kind (searched for
  `verify-strings`, `jurisdiction`, `prohibited`, and inspected `qa/gate/` — it holds only
  `check_cue_ids.mjs`, `check_mode_costs.mjs`, `check_round_tier.mjs`, `run.mjs`, none of which read

  catch a future regression in either `apps/piggy_firefighters/src` or the shared `state-shared`
  package. Recommend the coordinator add one, seeded from the finding above (donor bet-mode copy)
  and the full restricted-term table, run against both the source tree and the compiled build output
  (a source-only gate would have missed nothing here, but only because this game routes all its own
  copy through `{std, social}` pairs by convention — a gate that only checks source, not the
  compiled bundle, would not have caught the `DEFAULT_BET_MODE_META` finding, since that constant
  lives in a package this lane doesn't own).
- `qa/gate/check_mode_costs.mjs` covers mode-cost drift against the frozen math but not the *prose*
  that states those costs in the rules sheet — a hand-typed number in `rulesContent.ts` would not be
  caught by it. Not currently a problem (verified above that `rulesContent.ts` always reads
  `modeCost()` / `config` rather than typing a number), but it's a gap if that discipline slips.
